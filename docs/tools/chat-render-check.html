Can your AI chat’s replies run code?

Paste the component that shows your AI’s replies. Your browser reads it and flags the two ways a reply turns against your user: inserted into the page as raw HTML, where a steered model can write script, and Markdown images that load from any address, which carry chat text to someone else’s server with no click. Each one comes with the line, the fix and a prompt for your AI builder. Nothing you paste leaves this page.

Why replies matter

You didn’t write the reply. Whoever steered the model did.

A model writes what its input pushes it towards, and much of that input isn’t yours: the user’s message, a file they uploaded, a page a tool fetched, another customer’s ticket in your database. Hidden instructions in any of them can make the reply contain HTML or a Markdown image.

OWASP lists this as LLM05:2025, Improper Output Handling. No prompt setting reliably stops it, so the fix is in how your app shows the reply, which is the code you paste here.

What it looks for

The rendering mistakes AI builders write most.

The check skips comments and follows the value back to where it’s made: dangerouslySetInnerHTML={{ __html: html }} is traced to the useMemo or helper that builds html, and passes if DOMPurify.sanitize is on the way.

Then test it live

Ask your own chat to repeat this.

Open your app, send this message, then watch the page and your browser’s Network tab. An alert box means replies run as HTML. A request to example.com means images load from anywhere. Some models refuse or rewrite it, so a clean result isn’t proof; the code check above is the steadier test.

Questions

About the AI chat check

Something else? Email the founder.

Which file do I paste?

The component that turns a reply into what the user sees, often called Message, ChatMessage, Bubble, Reply or Markdown. In your project folder, search for dangerouslySetInnerHTML, react-markdown or marked to find it. If the HTML is built in a helper in another file, paste both.

Isn’t react-markdown safe already?

From script, yes, unless rehype-raw is added or urlTransform is loosened. From the image leak, no: it renders any https image the reply contains, and so do DOMPurify and rehype-sanitize. That’s why the image check is separate.

Does a Content-Security-Policy fix this?

It’s a strong backstop: script-src 'self' blocks inline script and img-src limits where images load from. Fix the component too, because a policy is easy to loosen later for an analytics tag. The free headers check shows whether your live site sends one.

Nothing flagged. Am I safe?

None of the risky patterns are in what you pasted. Replies often appear in more than one place: an admin log, a shared chat page, an email summary. Check each, and run the test prompt against your live app.

Does the full check cover this?

Yes. The full PatchLabs check reads every file in your repo for raw HTML rendering and the other patterns, scans the whole git history for keys, and rebuilds your database to test your RLS policies as three people. Free in early access.
