PL-027

Site doesn’t force HTTPS

The plain http:// address of your site serves the page instead of redirecting to https://.

mediumLive · HTTPS redirect→ PL-028

TLS certificate is invalid, expired or expires within 21 days

Browsers will block your site, or soon will, because its HTTPS certificate doesn’t check out.

high or mediumLive · certificate→ PL-029

No HSTS header, or max-age under 180 days

Browsers aren’t told to use HTTPS only, so a visitor’s first request can still go out over plain HTTP.

lowLive · headers→ PL-030

No Content-Security-Policy

Your page sends no Content-Security-Policy, so any script that gets onto it can run and send data anywhere.

mediumLive · headers→ PL-031

Any site can frame the page

Neither frame-ancestors nor X-Frame-Options is set, so another site can load your app invisibly inside its own.

lowLive · headers→ PL-032

No X-Content-Type-Options: nosniff

Browsers may guess a file’s type from its contents, so an uploaded “image” can be run as a script or page.

lowLive · headers→ PL-033

Cookie set without Secure, or a session cookie without HttpOnly

Your home page sets a cookie that can travel over plain HTTP, or a session cookie that any script on the page can read.

mediumLive · cookies→ PL-034

Page loads scripts or styles over plain HTTP

Your HTTPS page pulls a script or stylesheet from an http:// address, which anyone on the network can replace.

mediumLive · page HTML→ PL-035

Server headers reveal software versions

A Server or X-Powered-By header names the software and its version, which tells attackers which known bugs to try.

infoLive · headers→ PL-036

Your page sends no Referrer-Policy, so the browser’s default decides how much of your URLs other sites see.

Severity

Ranked by who can reach the data.

Severity follows one question: who, outside the people meant to see it, can read or change the data? Dependency findings take the severity of their published advisory.

LevelMeaning
criticalAnyone on the internet, or anyone who signs up, can read personal data, change a whole table or make themselves admin.
highAnyone who signs up can read personal data, a privileged function or webhook is open, or a user can act on another user's data.
mediumA real weakness that needs a specific situation to matter, such as a public bucket, unsanitised HTML or a loose CORS rule.
lowNothing exposed by itself, but the app is likely broken or other findings get easier to exploit.
infoNothing exposed and nothing to exploit: a one-line hardening step. Costs no points in the Live posture grade.

How a finding reaches you

Data you watched leak, code you can point at, or a header you can read.
