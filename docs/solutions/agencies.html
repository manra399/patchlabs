How agencies use it

From handover to “we caught it first”.

The value isn’t one clean report at launch. It’s telling the client about a leak, fix in hand, before anyone else finds it.

  1. Add the repo

    Client label and schedule. Public repos today; private with our GitHub App.

    client: Client A schedule: weekly

  2. Verify

    Someone with write access commits the verification file once. The first check queues.

    patchlabs-verify.txt

  3. Send the report

    Public by link, plain English: what leaked, the fix and the proof.

    patchlabs.dev/check?id=…

  4. Re-check weekly

    A new leak posts to your Slack and emails your team, with a proven fix ready.

Questions

Agency questions.

Something not covered? Email the founder.

Can my clients see each other’s apps?

Only if you invite them into your workspace, because every member sees every app in it. Keep clients out of the workspace and send them their report links instead.

Do I need access to the client’s repo?

Someone with write access has to commit the verification file once. That can be you, or the client.

What if a client’s app doesn’t use Supabase?

Code checks still run. The Lab needs a supabase/migrations folder to rebuild the database, so apps on other backends can’t be lab-tested yet.

Can I resell this to clients?

Many agencies include monitoring in a care plan. Talk to us before you put our name in a contract, so we can agree how it is described.

Is there a free trial?

Your first app is free forever, with monthly re-checks. Try it on one client app before you request the agency plan.
