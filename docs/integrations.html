GitHub

Source of every check
live

PatchLabs reads public GitHub repos: code, migrations and full git history. You prove a repo is yours by committing a one-time file; we never need write access.

  1. Paste the repo URL on the home page, or add it as an app in your workspace.
  2. Commit patchlabs-verify.txt with the one-time code (one-click link to GitHub’s new-file page).
  3. The check starts. Delete the file once it has.
Proving ownership

GitHub Actions

CI
live

Re-check your app every time a migration lands on the default branch. The action waits for the lab result, writes it to the job summary and can fail the build while a leak is open.

  1. Add and verify the app; copy its ID.
  2. Create a workspace API key; save it as the secret PATCHLABS_API_KEY and the app ID as the variable PATCHLABS_APP_ID.
  3. Add the workflow below.
.github/workflows/patchlabs.yml
on:
  push:
    branches: [main]
    paths: ['supabase/migrations/**']
jobs:
  leak-check:
    runs-on: ubuntu-latest
    steps:
      - uses: manra399/patchlabs/action@main
        with:
          api-key: ${{ secrets.PATCHLABS_API_KEY }}
          app-id: ${{ vars.PATCHLABS_APP_ID }}
          fail-on-leak: true

Slack-compatible webhooks

Alerts
live

One webhook URL per workspace. Every finished check POSTs a JSON event with a one-line text field, so a Slack incoming webhook works as-is. Requests are HMAC-SHA256 signed.

  1. In Settings → Webhook, paste an https URL (for Slack: an incoming webhook URL).
  2. Press “Send test” to check delivery.
  3. Optional: verify X-PatchLabs-Signature with your workspace secret.
Webhook docsVerifying signatures

Claude Code, Cursor and other agents via MCP

Remote MCP server
live

Ask your coding agent to check an app. Works with Claude Code, Cursor, VS Code, Windsurf and other MCP clients: run the free RLS check, start full checks, read fixes and re-check monitored apps.

  1. Add the server to your client (Claude Code below; snippets for the others in the docs).
  2. Optional: add a workspace key as the X-API-Key header for list_apps and run_check.
  3. Ask: “Check this repo for leaks with PatchLabs.”
Terminal
claude mcp add --transport http patchlabs https://api.patchlabs.dev/mcp
MCP docs

REST API

Build on PatchLabs
live

Start checks, read results and findings, and manage apps from your own tools with a workspace API key.

  1. Create a key in Settings → API keys (shown once).
  2. Send it as X-API-Key.
  3. POST /v1/apps/{id}/checks, then poll GET /v1/checks/{id}.
API reference

Email alerts

Alerts
live

Every member of the workspace gets an email when a check of one of its apps finishes. The subject says “new leak” only when there is one.

  1. Invite your team in Settings → Team.
  2. Choose a re-check schedule per app.
  3. That’s it: alerts follow the schedule.

Apps built on

Works with apps built on these platforms.

Compatibility: we read the code they produce. Independent, not a partnership.

Lovable

Apps built on Lovable
works with

Lovable projects synced to GitHub usually include supabase/migrations, which is all the Lab needs. Works on the exported code, so it keeps working after you leave the builder.

  1. Connect your Lovable project to GitHub.
  2. Paste the repo on the home page.
Lovable apps

Supabase

Database, auth, storage, edge functions
works with

The Lab rebuilds Supabase projects from their migrations with Supabase’s roles, auth functions and default grants. Code checks read edge functions and auth settings.

  1. Keep your schema in supabase/migrations (supabase db diff or db pull).
  2. Push to GitHub and paste the repo.
Supabase apps

Bolt

Apps built on Bolt
works with

Bolt projects that use Supabase and are pushed to GitHub work the same way.

  1. Export or push the project to GitHub.
  2. Paste the repo.
Bolt apps

Replit

Apps built on Replit
works with

Replit apps with Supabase migrations in the repo are fully checked. Without migrations, Code checks still run.

  1. Connect the Repl to GitHub.
  2. Paste the repo.
Replit apps

works with

Any repo you write in Cursor works. Add the MCP server to ask for checks from inside the editor.

  2. add the MCP server to .cursor/mcp.json.
