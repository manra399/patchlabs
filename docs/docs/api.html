    Reference

    REST API

    Everything the PatchLabs site and dashboard do goes through this API, so everything they do, you can script. JSON in, JSON out, plain-English errors.

    Overview

    Base URL
    https://api.patchlabs.dev
    Format
    JSON request and response bodies. Send Content-Type: application/json with a body. Times are ISO 8601 in UTC. IDs are UUIDs.
    Browsers
    Cross-origin browser requests are accepted from patchlabs.dev only. Call the API from your server, scripts or CI.
    Stability
    Endpoints on this page are live. We add fields over time, so ignore ones you don’t recognise. We announce breaking changes on the changelog before making them.

    Authentication

    There are three levels, and each endpoint below says which it needs.

    LabelSendUse it for
    No authnothingFree checks, reports and receipts by link, badges, stats, the free RLS check
    API keyX-API-Key: pl_live_…Scripts and CI: the /v1 endpoints and the MCP app tools
    SessionAuthorization: Bearer <session>Everything in the dashboard: workspaces, apps, decisions

    API keys

    Create one in Settings → API keys (or with POST /workspaces/{wid}/api-keys). It looks like pl_live_ followed by 32 characters and is shown once: we only store a hash and the first 12 characters, so you can tell keys apart. A key belongs to one workspace and can only reach that workspace’s apps. Revoke it at any time; it stops working immediately. Keep it in your CI’s secret store, never in code.

    Terminal
    export PATCHLABS_API_KEY=pl_live_…
curl -s -X POST https://api.patchlabs.dev/v1/apps/$APP_ID/checks -H "X-API-Key: $PATCHLABS_API_KEY"

    Sessions

    A session comes from the magic-link sign-in (POST /auth/start, then POST /auth/finish) and lasts 30 days. The website keeps it in your browser’s local storage. For your own scripts against workspace and app endpoints, sign in and copy the pl_session value from the browser’s developer tools into $PL_SESSION. Prefer API keys for anything long-lived.

    Errors

    Errors come back with an HTTP status and a body you can show to a person:

    409 Conflict
    {"detail": "A check is already queued or running for this app."}

    The one exception is a request body that doesn’t match the expected shape (a missing field, a bad email). Those return 422 with a list that points at the field:

    422 Unprocessable Content
    {"detail": [{"type": "missing", "loc": ["body", "email"], "msg": "Field required", "input": {…}}]}
    StatusMeaning
    400A sign-in link that has expired or was already used
    401Missing or expired session, or a missing, invalid or revoked API key
    403Signed in, but not allowed: not an owner, wrong workspace, or a plan limit (apps, seats, schedules)
    404Not found, or not yours to see
    409Not possible in the current state: not verified yet, a check already running, not finished yet
    422Input we can’t use: not a GitHub repo, repo not found, unsafe webhook URL, wrong body shape
    429A rate limit or monthly run limit (see below)
    503GitHub couldn’t be reached; try again in a minute

    Free checks

    A free check is a one-off full check of a public repo. It needs no account, only an email and the one-file verification.

    POST /checks

    No auth

    Request a full check. We email the requester a link to the check page with the verification step.

    Body

    repo string
    Public GitHub repo: owner/name or a github.com URL.
    email string
    Where the report link goes.
    Request
    curl -s -X POST https://api.patchlabs.dev/checks -H 'Content-Type: application/json' \
  -d '{"repo": "you/your-app", "email": "you@company.com"}'
    Response · 201 Created
    {"id": "7c1e2f0a-…", "status": "awaiting_verification", "repo": "you/your-app",
 "link": "https://patchlabs.dev/check.html?id=7c1e2f0a-…"}

    422 not a GitHub repo, repo not found or not public, or a bad email429 3 checks already open for this email, or 10 requests from this network today

    GET /checks/{id}

    No auth · by link

    The check and, once it has finished, its report. Fields appear as the check moves along.

    Response fields

    verify object
    While awaiting_verification: {file, code, add_url}.
    summary object
    When finished: tables_leaking, readable_by_anyone, readable_by_signed_in, lab_proof_passed, break_risk, questions_for_owner, models, and findings: each finding carries cwe (list), owasp and owasp_name (OWASP Top 10 2021); on an app’s check also first_seen, days_open, fixed_at (null while open), fixed_in_check_id and regressed.
    report_md, fix_sql string
    When finished: the report as Markdown and the fix migration (null when there are no leaks).
    error string
    When failed: a plain-English explanation.
    events array
    Timeline: [{at, kind}].
    decisions, answers array
    Always present; see decisions.
    Request
    curl -s https://api.patchlabs.dev/checks/$CHECK_ID
    Response · 200 OK
    {"id": "7c1e…", "repo": "you/your-app", "status": "done",
 "created_at": "…", "verified_at": "…", "finished_at": "…",
 "summary": {"tables_leaking": ["profiles"], "readable_by_anyone": ["profiles"],
             "readable_by_signed_in": [], "lab_proof_passed": true, "break_risk": "low",
             "questions_for_owner": [], "models": [{"model": "haiku", "passed": true, "seconds": 36}]},
 "report_md": "# Leak check: you/your-app …", "fix_sql": "DROP POLICY …",
 "events": [{"at": "…", "kind": "requested"}, {"at": "…", "kind": "verified"}, …],
 "decisions": [], "answers": []}

    404 no check with that ID

    POST /checks/{id}/verify

    No auth · by link

    Look for patchlabs-verify.txt with the check’s code on the default branch. On success the check joins the queue. Calling it again after that just returns the current status.

    Request
    curl -s -X POST https://api.patchlabs.dev/checks/$CHECK_ID/verify
    Response · 200 OK
    {"status": "queued"}

    409 file or code not found on the default branch yet503 GitHub unreachable; try again

    Decisions and receipts

    Decisions and answers need an owner, admin or approver session in the app’s workspace, and a finished check. Receipts are public by link. Guides: decisions, receipts.

    POST /checks/{id}/decision

    Session · approver+

    Approve a fix, or reject tables as intentionally readable (remembered for the app as suppressions).

    Body

    action approve | reject
    Required.
    tables string[], optional
    Defaults to every table the check flagged; must be a subset of them.
    reason string, optional
    Up to 2,000 characters.
    Request
    curl -s -X POST https://api.patchlabs.dev/checks/$CHECK_ID/decision -H "Authorization: Bearer $PL_SESSION" -H 'Content-Type: application/json' \
  -d '{"action": "reject", "tables": ["shops"], "reason": "Public by design"}'
    Response · 201 Created
    {"decisions": [{"action": "reject", "tables": ["shops"], "reason": "Public by design", "by": "Priya", "at": "…"}]}

    403 not an app check, not a member, or a member/viewer/client role409 check not finished422 a named table wasn’t flagged

    POST /checks/{id}/answers

    Session · approver+

    Answer the report’s business questions. Answering a question again replaces the earlier answer.

    Body

    answers array
    1 to 50 items of {question, answer}; each question must match one in summary.questions_for_owner.
    Request
    curl -s -X POST https://api.patchlabs.dev/checks/$CHECK_ID/answers -H "Authorization: Bearer $PL_SESSION" -H 'Content-Type: application/json' \
  -d '{"answers": [{"question": "Should sellers’ emails be public?", "answer": "No"}]}'
    Response · 200 OK
    {"answers": [{"question": "Should sellers’ emails be public?", "answer": "No", "by": "Priya", "at": "…"}]}

    403 not an app check, not a member, or a member/viewer/client role409 not finished, or the check has no questions422 unknown question

    Sign-in

    Sign-in is by magic link. The site handles these calls for you; they are listed for completeness.

    POST /auth/start

    No auth

    Email a sign-in link to {site}/app/login?token=…. Always answers 202, whether or not the address has an account. The link works once and expires in 20 minutes.

    Body

    email string
    Required.
    next string, optional
    A path on patchlabs.dev to return to after sign-in, such as /app/.
    Request
    curl -s -X POST https://api.patchlabs.dev/auth/start -H 'Content-Type: application/json' -d '{"email": "you@company.com"}'
    Response · 202 Accepted
    {"ok": true, "detail": "If that address can sign in, a link is on its way. It expires in 20 minutes."}

    POST /auth/finish

    No auth

    Exchange the link’s token for a session (valid 30 days). Creates the user and a personal workspace on first sign-in, and links earlier free checks with the same email.

    Body

    From the sign-in link.
    invite string, optional
    An invite token to accept at the same time.
    Request
    curl -s -X POST https://api.patchlabs.dev/auth/finish -H 'Content-Type: application/json' -d '{"token": "…"}'
    Response · 200 OK
    {"session": "…", "user": {"id": "…", "email": "you@company.com", "name": null, "created_at": "…"},
 "next": "/app/", "invite": null}

    Workspaces

    Every workspace endpoint needs you to be a member, and your role must allow the call. Roles, most to least: owner, admin (everything but making or removing owners), approver (also approves or rejects fixes and answers the owner’s questions), member (views and runs checks), viewer (read-only) and client (read-only, only the apps shared with them, plus support tickets about those apps; clients never use a team seat). “approver+” means owner, admin or approver. Guide: teams.

    Session · any role

    Live posture

    Passive checks of the app’s live domain, once the team proves it controls it: one plain http:// request (to see the redirect), one https:// load of the home page (at most 5 redirects) and that load’s TLS handshake. Nothing else: no other paths, no forms, no API calls, never the database. GET /apps/{aid} carries live (below); GET /workspaces/{wid}/apps carries the same with last cut to {grade, score, checked_at, counts}. Product page: Live posture; finding IDs PL-027 to PL-036.
