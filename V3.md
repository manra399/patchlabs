# PatchLabs v3: from one check to a security platform for AI-built apps

Written 10 Nov 2026. Manraj's verdict on v2: "still very limited". The home page literally says "Two things, done
properly" and has a "What we don't do" box. Aikido sells four product lines with dozens of capabilities, real product
UI on every section, dark immersive "agents at work" sections, an integrations strip and persona paths. v3 closes that
gap **by widening the real product first**, then the site. Every capability named on the site must exist in code and
be tested. Anything not built is labelled "coming" with what unlocks it.

## Truth rules (unchanged, non-negotiable)

- No invented logos, testimonials, customer counts, certifications or partnerships. "Works with Lovable" (compatibility) is
  fine; implying a partnership is not. Text names or neutral generic icons, never a company's logo artwork.
- Never name any app, repo or owner from the study. The demo app is `manra399/patchlabs-demo-app` (ours, fake data).
- Never show per-check cost (model spend) to users.
- Every check works from the repo and the rebuilt lab database only. Nothing probes a running app.

## One finding shape (engine → worker → API → app)

```json
{"id": "PL-012", "line": "lab|code", "severity": "critical|high|medium|low|info",
 "title": "plain English", "object": "public.profiles | src/pages/Admin.tsx",
 "file": "supabase/migrations/2024..._init.sql", "line_no": 42,
 "evidence": "short, redacted, no personal data", "proven": true,
 "proof": "how the lab reproduced it, e.g. 'signed-in stranger updated 1 row owned by another user'",
 "fix": "one line", "fixed_in_lab": false, "advisory": "GHSA-... (PL-023 only)"}
```

`findings.json` from `build/leakcheck/run.py` gains `"checks": [<finding>...]` (all lines) next to the existing `lab`
and `secrets` keys, which stay for compatibility. The worker passes `summary.findings` (the same list, max 200) and
`summary.counts` (`{"critical": n, ...}`) to the API; the API stores summary JSON as-is. The app groups by `line`.

## Code module contract

`build/leakcheck/codescan/__init__.py` exposes `scan(repo_path: str) -> {"findings": [...], "stats": {...}}`.
Pure Python 3.13 stdlib + `urllib` for OSV (`https://api.osv.dev/v1/querybatch`), never runs repo code, never
installs packages, 120 s total budget, works offline (dependency check reports `skipped` instead of failing).
