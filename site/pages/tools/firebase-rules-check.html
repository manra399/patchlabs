Why rules matter

Your Firebase config is public. Your rules are the only lock.

Every Firebase web app ships its project config, API key included, in the JavaScript every visitor downloads. That is by design: the key only identifies the project. What decides who can read and write is the security rules file, and anyone can call your database directly with the config, without ever opening your app.

So a rule that says if true, or that only checks request.auth != null, is an open door, whatever your app’s screens show.

RuleWho gets in
allow read, write: if request.time < timestamp.date(…)anyone Test mode. Open to the whole internet until the date, then everything breaks.
allow read; or if trueanyone No condition at all.
if request.auth != nullany account Checks that someone signed in, not who. Anyone can sign up.
if request.auth.uid == userIdthe owner What you want for personal data.

The rule mistakes AI builders and quick-starts leave behind.

The check reads each allow statement with the path it sits under, follows your helper functions, and judges what the condition actually checks.

Where do I find my rules?

In the Firebase console, open Firestore Database (or Storage, or Realtime Database) and choose the Rules tab. Copy everything in the editor. If your project uses the Firebase CLI, the same rules are in firestore.rules, storage.rules or database.rules.json in your repo. The console shows what is live, so check that one if they differ.

Is it safe to paste my rules here?

Rules aren’t secret, but you don’t have to trust us: the check is a script on this page that reads the text box and draws the result. It makes no network request and stores nothing. Open your browser’s developer tools, go to the Network tab, and run a check to see for yourself.

Isn’t my Firebase API key the real problem?

No. The Firebase web API key is meant to be in your app and only identifies the project. Your rules decide what that key can do. Keys for other services (AI providers, Stripe, a service account JSON) are a different story: paste those files into the free key check.

Nothing flagged. Am I safe?

None of the risky patterns appear in what you pasted, and every allow line checks who is asking. This is a reading of the rules text, not a test against your project, so a condition can still be wrong in a way only a test shows (an owner field the client can set, say). Firebase’s Rules Playground in the console lets you try a request as a signed-out user and as another user.

I built my app in FlutterFlow. Where are my rules?

FlutterFlow writes them for you from Settings › Firestore and deploys them when you press Deploy there; you can copy the live result from the Rules tab in the Firebase console. Every new collection starts with Create and Read set to Everyone, so a collection you never revisited is readable by anyone. The check spots FlutterFlow’s rule format and tells you which setting to change.
