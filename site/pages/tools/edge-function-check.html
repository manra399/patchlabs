Why functions matter

The function’s URL is public. Its code is the only lock.

Every Edge Function answers at https://<project>.supabase.co/functions/v1/<name>, and the name is in the JavaScript your app ships. Anyone can call it with any headers and any body, without opening your app.

Functions are also where the service role key lives, and that key skips every row level security policy. So a function that uses it is your access rule. If it never asks who is calling, your database rules are off for whoever finds the URL.

What it looks for

The function mistakes AI builders write most.

The check reads the code line by line, skips comments, and looks at the function as a whole: a service role key is fine after a caller check, a signature check or a shared secret, and only flagged without one.

Where do I find my function’s code?

In your repo at supabase/functions/<name>/index.ts. If you built with Lovable or Bolt, open the code view and look for the supabase/functions folder. In the Supabase dashboard, Edge Functions lists each function and shows its code. Paste one function at a time.

Is it safe to paste code with keys in it?

The check is a script on this page. It makes no network request and stores nothing, and keys are masked in the result. Open your browser’s developer tools, go to the Network tab, and run a check to see for yourself. If it finds a key, rotate it anyway: it has been in your code.

Isn’t verify_jwt enough?

No. On projects with legacy keys, the platform check accepts any valid project JWT, and your public anon key is one. It stops nobody who has opened your app. Check the caller in the code with supabase.auth.getUser(token) and use the id it returns. The Edge Function guide walks through it.

Nothing flagged. Am I safe?

None of the risky patterns appear in what you pasted. This is a reading of the code, not a test of your deployed function, so logic it can’t see (an admin check that reads the wrong field, say) can still be wrong. Call the function yourself with no token and with a second account’s token to confirm.
