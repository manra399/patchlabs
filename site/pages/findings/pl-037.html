PL-037mediumCode

Personal data sent in a request header or to an AI model API

A user's email, phone or ID number goes into a request header or an AI prompt, so it is copied into logs and vendor storage you don't control.

Severity
Medium
Who can exploit it
Everyone who can read your CDN, host, APM or AI provider logs, and anyone who breaches them
Found by
PatchLabs Code: request headers and AI model calls in your code (JS, TS and Python)
Lab proof
Not lab-proven: file and line in the report

ExplainWhat it is

Two habits put personal data where your database rules don't reach. The first is a request header that carries it, such as "X-User-Email": user.email. Headers can be written to CDN, proxy, load balancer and APM logs, which are kept for weeks or months and read by more people and vendors than your database.

The second is a prompt that carries it: `Patient ${patient.full_name}, born ${patient.date_of_birth}`, or JSON.stringify(profile) sent as a message. The AI provider keeps prompts for abuse monitoring, and gateways, tracing and eval tools in between often keep them too. PL-037 flags both.

CauseWhy AI builders produce it

Both are the fastest fix that works. “The server doesn’t know who’s calling” becomes a header; “the model needs context” becomes the whole record pasted in. Nothing breaks, so nobody looks again.

ExploitExample of vulnerable code

Simplified from the patterns we see in AI-built apps. Synthetic: not taken from any real app.

src/lib/api.ts and summarize/index.ts (risky)
// src/lib/api.ts
const res = await fetch("/api/orders", {
  headers: { "Content-Type": "application/json", "X-User-Email": user.email },
});

// supabase/functions/summarize/index.ts
const completion = await openai.chat.completions.create({
  model: "gpt-5-mini",
  messages: [
    { role: "user", content: `Patient ${patient.full_name}, born ${patient.date_of_birth}` },
    { role: "user", content: JSON.stringify(profile) },
  ],
});

FixThe fix

fixed
// headers: send nothing personal; the server reads the user from the session
const res = await fetch("/api/orders", {
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${session.access_token}` },
});

// prompts: send only what the task needs, with placeholders
const notes = redact(patient.visit_notes);   // strip names, emails, phone and ID numbers
const completion = await openai.chat.completions.create({
  model: "gpt-5-mini",
  messages: [
    { role: "system", content: "Refer to the person as [PATIENT]." },
    { role: "user", content: notes },
  ],
});

Prompt for your AI builder
My app puts users' personal data (email, phone, name, address, date of birth or ID numbers) into request headers or into prompts sent to an AI model. Find every place that does this. For headers, remove the personal values and have the server read the signed-in user from the session instead. For AI calls, send only the fields each task needs, replace names and contact details with placeholders before the call, and never send a whole user record with JSON.stringify. List each change you made. Show me the exact change before you apply it, and don't change anything else.

Then check again with the free open-source CLI (patchlabs scan .), or run the full free check on your repo.

synthetic exampleReport excerpt · read from the repo, not lab-proven

PatchLabs Code reads the headers your code sets and the lines around each AI model call. ID, health, card and bank fields are high, contact fields medium. Opaque ids, example.com addresses, commented-out lines and code that reads the model’s answer are not flagged. It never calls your app or the model.

IntentWhen the pattern is intended

Some features need a personal detail, such as an assistant that drafts an email to a named customer. That can be fine when it is a decision: write down which fields go, check the provider’s retention terms, say so in your privacy notice, and keep the fields out of tracing.

RateWhy it’s rated medium

Medium for contact details, high for ID numbers, health, card or bank data: nobody reads it straight away, but the copies outlive your own controls and leak when a vendor is breached.
