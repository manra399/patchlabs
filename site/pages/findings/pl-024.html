PL-024mediumCode

User content rendered as raw HTML

Text one user wrote goes into the page as HTML, so it can run scripts in other users' browsers.

Severity
Medium
Who can exploit it
Any user who can post content others see
Found by
PatchLabs Code: your frontend code
Lab proof
Not lab-proven: file and line in the report

ExplainWhat it is

React escapes text by default: {comment.body} shows <script> as harmless characters. dangerouslySetInnerHTML, element.innerHTML and Markdown libraries that output raw HTML switch that protection off. PL-024 means content someone else wrote, such as a comment, a bio, a listing description or a chat message, reaches one of those without being sanitised.

A user can then post HTML that runs JavaScript in every viewer's browser (cross-site scripting). In a Supabase app this matters more than usual: supabase-js keeps the session in localStorage by default, and any script running on your page can read it and act as the viewer, including an admin who opens the content to moderate it.

CauseWhy AI builders produce it

Asked to "support formatting" or "render Markdown", the shortest route is to convert to HTML and insert it. The name dangerouslySetInnerHTML is a warning, but the code works and test content is always friendly.

ExploitExample of vulnerable code

Simplified from the patterns we see in AI-built apps. Synthetic: not taken from any real app.

src/components/Comment.tsx (vulnerable)
// src/components/Comment.tsx
import { marked } from 'marked';

export function Comment({ body }: { body: string }) {
  // body was written by another user
  return <div dangerouslySetInnerHTML={{ __html: marked.parse(body) as string }} />;
}

// A comment like this runs in every reader's browser:
//   <img src=x onerror="alert(document.domain)">

CheckCheck it yourself

check-pl-024.sh
# Places that insert HTML
grep -rnE "dangerouslySetInnerHTML|\.innerHTML *=|insertAdjacentHTML|v-html" src

# Then, on a local or staging copy, post this as a comment and view it:
#   <img src=x onerror="alert(document.domain)">
# An alert box means user content runs as code.

FixThe fix

src/components/Comment.tsx (fixed)
// src/components/Comment.tsx
import { marked } from 'marked';
import DOMPurify from 'dompurify';

export function Comment({ body }: { body: string }) {
  const html = DOMPurify.sanitize(marked.parse(body) as string);
  return <div dangerouslySetInnerHTML={{ __html: html }} />;
}

Simpler still, skip HTML: render plain text as {body}, or use react-markdown, which builds React elements and doesn't render raw HTML unless you add rehype-raw.

IntentWhen the pattern is intended

HTML you control is fine: a static string, or content from your own CMS written by staff. Sanitising it anyway costs little and protects you if that changes.

RateWhy it’s rated medium

Medium: it needs one user to post and another to view. It becomes serious when admins view user content, because their session can do more.
