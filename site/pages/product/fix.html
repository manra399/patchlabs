How it works

Write, prove, ask, approve.

Each stage leaves an artifact you can inspect.

  1. Write

    The smallest Claude model writes the migration first; a larger one only if the proof fails. Spend is capped per check.

    + create policy … using (auth.uid() = user_id)

  2. Prove

    Re-run the probes as anon, stranger and owner on the fixed database. All three must pass.

    anon DENIED stranger DENIED owner OK

  3. Ask

    When the right answer is a business choice, the report asks in plain English, with a recommended answer.

    Should sellers’ emails be public? → no

  4. Approve

    Approve the fix, or mark a table as meant to be readable. Download the SQL or commit it on GitHub.

    supabase/migrations/ …_patchlabs_leak_fix.sql

Prove

A fix only counts when it passes three checks.

Every fix we hand over has been tested in the lab as three different people. If any check fails, it is not called proven.

Anonymous visitorDENIED
-- with your app's public key
select * from public.profiles;
→ 0 rows

Anyone on the internet has your public key; it ships inside your app. After the fix they read nothing.

Signed-in strangerDENIED
-- signed in as a different user
select * from public.profiles;
→ 0 rows

Anyone can create an account. Signing up must not unlock other people’s rows.

OwnerOK
-- signed in as the row's owner
select * from public.profiles;
→ 1 row, their own

A fix that locks real users out is not a fix. The owner must still read their own data.

supabase/migrations/20261109165700_patchlabs_leak_fix.sql
-- Fix: replace the "everyone can read" policy with owner-only access.
DROP POLICY "Profiles are viewable by everyone" ON public.profiles;
CREATE POLICY "Users can view own profile" ON public.profiles
  FOR SELECT USING (auth.uid() = user_id);

What Fix doesn’t do. It never merges or applies anything by itself: a person always approves. Automatic pull requests and private repos need our GitHub App, which is coming. A proven fix covers the access rules we test, not the whole app; it isn’t a pentest or a compliance certification.

Questions

Questions about this product line.

Something not covered? Email the founder.

What if the fix can’t be proven?

Then we don’t call it proven. The report says a person is reviewing it, and explains why. In our lab study 2 of 20 fixes went to a person.

Can my coding agent apply the fix?

Your agent can start checks and read the fix through our MCP server. Whether it applies the migration is up to you and your engineer; we never push to your repo.

Which model writes the fix?

Claude models from Anthropic: the smallest first, a larger one only if the lab proof fails, with a spend cap on every check. The model sees the relevant code, never your customers’ data.

Do you open pull requests?

Not yet. Today you download the migration or commit it on GitHub in one click. Automatic pull requests come with our GitHub App.
