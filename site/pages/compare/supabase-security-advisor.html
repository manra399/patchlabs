PatchLabs vs Supabase Security Advisor

The Advisor says a rule looks risky. PatchLabs proves who can read the rows.

Supabase’s Security Advisor is free, built into every project and worth running. It checks your database against documented rules. PatchLabs rebuilds your database from your migrations, tests it as three different people, writes the fix and proves it. Most teams should use both.

Last checked 10 Nov 2026Sources at the endIndependent of Supabase

Choose the Security Advisor when

You want instant, free checks on the database that’s actually running.

  • You want results in seconds, inside Supabase Studio, the CLI or their MCP server
  • You also want performance and health checks, which we don’t do
  • You changed policies in the dashboard without a migration: the Advisor sees your live project, we only see your repo
  • You’re comfortable writing and testing the fix yourself

Choose PatchLabs when

You want the fix written, and proof that it works, before it ships.

  • You want every fix tested as an anonymous visitor, a signed-in stranger and the owner
  • Your code lives in GitHub (exported from Lovable, Bolt, Replit or Cursor) and you want a migration to review
  • You need to know whether a “permissive” table is actually leaking personal data, or meant to be public
  • You want scheduled re-checks, alerts, keys found in git history and signed receipts

Behaviour, not lint

A rule can look fine and still leak. Or look risky and be exactly right.

A product catalogue that anyone can read is meant to be public. A profiles table with a policy that looks scoped can still return every row to a signed-in stranger. Only running the query as each person tells you which is which.

Our limit. The lab is only as complete as the migrations in your repo. If you changed a policy in the Supabase dashboard without a migration, the Advisor sees it and we don’t. Our report says what it couldn’t check.

Questions

Asked about the Advisor.

If the Advisor shows no errors, am I safe?

It means your database doesn’t break the rules it checks. It doesn’t run queries as different users, so a policy that looks correct but still returns other people’s rows can pass. That is the gap our lab tests. Neither tool can promise an app is secure.

Does PatchLabs connect to my Supabase project?

No. We never need your database password or service-role key. We rebuild a disposable copy from the migrations in your public GitHub repo, with Supabase’s roles, auth functions and default grants, seeded with fake rows.

Why would a lint flag a table that’s fine?

Some tables are meant to be readable by anyone, such as a public product list. Supabase’s docs acknowledge findings can be intentional. Our report asks you in plain English, with a recommended answer, and remembers when you mark a table as intended.

Which should I run first?

The Advisor, because it’s instant and already in your project. Then run PatchLabs for proof that the fix works as each kind of user.
