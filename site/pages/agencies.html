How agencies use it

From handover to “we caught it first”.

The value isn’t one clean report at launch. It’s being the one who tells the client about a leak, with the fix in hand, before anyone else finds it.

Ownership. To add an app, someone with write access commits patchlabs-verify.txt with a one-time code. If you still have access to the client’s repo, you can do it yourself in a minute.

  1. Add the client’s repo

    Give it a client label and a schedule. Public repos today; private repos come with our GitHub App.

  2. Verify and run the first check

    Commit the verification file. The first check queues straight away.

  3. Send the client the report

    Report links are public by link and written in plain English: what leaked, the fix, and the proof.

  4. Their engineer, or you, applies the fix

    A migration file to download or commit on GitHub. Nothing reaches production without a person.

  5. Weekly re-checks after handover

    A new leak posts to your Slack and emails your team, with a new proven fix ready.

Questions

Agency FAQ.

Running more than 50 client apps? Talk to us about an enterprise plan.

Can my clients see each other’s apps?

Only if you invite them into your workspace, because every member sees every app in it. Keep clients out of the workspace and send them their report links instead.

Do I need access to the client’s repo?

Someone with write access has to commit the verification file once. That can be you, or the client.

What if a client’s app doesn’t use Supabase?

The key scan still runs, but the leak lab needs a supabase/migrations folder to rebuild the database. Apps on other backends can’t be lab-tested yet.

Can I resell this to clients?

Many agencies include monitoring in a care plan. Talk to us before you put our name in a contract, so we can agree how it is described.

Is there a free trial?

Your first app is free forever, with monthly re-checks. Try it on one client app before you request the agency plan.
